## Done

CPP-01 record codec, on top of the CPP-00 scaffold.

Record format v1 is implemented and frozen: a 24-byte header with explicit little-endian
load/store helpers, so nothing in the serialization path depends on host endianness, struct
padding, or alignment. CRC32C is the last header field, which makes the checksummed range the
contiguous header prefix `[0, 20)` followed by the payload.

CRC-32C is a compile-time table-driven implementation verified against the canonical check value
`0xE3069283` and the four 32-byte patterns from RFC 3720, not merely against itself. Chaining is
exact, which the codec relies on to checksum the header and payload as separate chunks.

Decoding validates magic, version, every one of the 16 unknown flag bits, sequence, and the payload
bound before a caller can size a buffer from the length field.

The scaffold: CMake C++20 project with a strict warning set promoted to errors, a Debug
build with AddressSanitizer and UndefinedBehaviorSanitizer configured to fail rather than log, a
Release target, `clang-format` enforcement, a dependency-free test harness, `./scripts/verify.sh`
and `./scripts/verify-full.sh`, and a GitHub Actions job that runs the same script CI and local
development share.

Specification validated against `docs/PRD.md` before any implementation
(`docs/SPEC_VALIDATION.md`): outcome `spec-ready` with four recorded resolutions, two of which
became ADRs because they fix a guarantee rather than an implementation detail.

Placeholder CLI listing the intended commands. Every one exits with a usage error naming the
milestone that will implement it, so nothing can be mistaken for working.

## Evidence

`./scripts/verify.sh` PASS on 2026-09-17, macOS 15 / arm64, Apple clang 17, CMake 4.4, APFS.
32 cases across `test_scaffold`, `test_crc32c`, and `test_codec`, all under ASan + UBSan.

The codec is pinned by fixed golden byte vectors generated by an independent implementation rather
than by this code, so a refactor that changes the on-disk bytes fails loudly. `test_crc32c` also
checks all 2048 single-bit flips of a 256-byte block are detected.

## Known issues and limits

`fdatasync` is unavailable on the macOS development host, so the durability barrier is a documented
per-platform mapping (ADR-001) and CI on Linux is what exercises the primitive the PRD names.
Benchmark numbers will therefore not be comparable across the two platforms.

`clang-format` versions differ between the macOS toolchain and the Ubuntu CI image, so the CI
format check is advisory and the local check in `verify.sh` is the enforcing one.
